# M1 managed-lifecycle spike plan

Plan only, 2026-09-09. Execute only after M1 activation in a dedicated worker worktree and disposable userspace-only Ganesha fixture. This design session writes no program and runs no tests. The spike is the first technical branch of M1; [failure-model.md](failure-model.md) and [syscall-matrix.md](syscall-matrix.md) define the obligations it must preserve.

## Question and fixed baseline

Can supported public libnfs APIs provide anchored, byte-safe operations, bounded iteration and observable persistence/recovery while libnfs owns client/open/lock state and renewal/reclaim? A narrowly mixed managed/raw API is a Go only if state ownership remains entirely in libnfs through supported interfaces. Reading private struct layouts, borrowing hidden state IDs, or partially owning renewal is not Go.

Pin initial library candidate [`libnfs-7.0.2`, `b6a27bed572ee94a5e4d9db0d96e524455d86a42`](https://github.com/sahlberg/libnfs/tree/libnfs-7.0.2), matching headers/library and generated bindgen declarations. Build/record the actual pinned Ganesha version, image digest, FSAL and backing volume at activation; copy configuration ideas, never reuse the existing scratch service. First profile: TCP, NFS major 4/minor 0 only, AUTH_SYS fixed non-root UID/GID, non-privileged client ports allowed, delegations disabled, persistent recovery directory, 60-second NFS lease/90-second grace (verify fields for the selected build). These are proposed fixture settings, not a claim about today's service.

Set client directory/data/attribute caches off where public controls exist; otherwise establish per-operation revalidation. Record hidden caching found in source. Native name encoding must preserve every non-NUL byte accepted by the qualified export. M1 keeps hard links/xattrs/atomic swap false and unsupported atomic no-replace refused unless proven; do not add them to the spike's Go bar unnecessarily.

## Exact API inventory

Names below are public C functions in the pinned headers; `struct nfs_context` is a type, not a `nfs_context_*` function family. Internal `nfs4_*` helpers in `lib/nfs_v4.c` are inspection targets, not stable binding entry points.

| Header group | Calls/types to exercise |
| --- | --- |
| [`nfsc/libnfs.h`](https://github.com/sahlberg/libnfs/blob/libnfs-7.0.2/include/nfsc/libnfs.h) | `nfs_init_context`, `nfs_destroy_context`, `nfs_set_version(..., NFS_V4)`, `nfs_get_version`, `nfs_set_uid/gid/auxiliary_gids`, `nfs_set_nfsport`, `nfs_set_auto_traverse_mounts`, `nfs_set_dircache`, `nfs_set_autoreconnect`, `nfs_set_retrans`, `nfs_set_timeout`, `nfs_set_poll_timeout`; `nfs_mount_async`, `nfs_get_fd`, `nfs_which_events`, `nfs_service`; `nfs_open2_async`, `nfs_close_async`, `nfs_fstat64_async`, `nfs_lstat64_async`, `nfs_pread_async`, `nfs_pwrite_async`, `nfs_fsync_async`, `nfs_opendir_async`, `nfs_readdir`, `nfs_telldir`, `nfs_seekdir`, `nfs_closedir`; `nfs_mkdir2_async`, `nfs_rename_async`, `nfs_unlink_async`, `nfs_rmdir_async` for mutation containment. Confirm signatures against the build before generation. |
| [`nfsc/libnfs-raw.h`](https://github.com/sahlberg/libnfs/blob/libnfs-7.0.2/include/nfsc/libnfs-raw.h), transitive `libnfs-zdr.h` | `nfs_get_rpc_context`, `nfs_get_fh` bridge borrowed contexts/handles. `rpc_nfs4_compound_task`, `rpc_nfs4_read_task`, `rpc_nfs4_write_task`, `rpc_cancel_pdu`; raw-only lane additionally `rpc_init_context`, `rpc_destroy_context`, `rpc_connect_async`, `rpc_disconnect`, `rpc_get_fd`, `rpc_which_events`, `rpc_service`, `rpc_set_uid/gid/auxiliary_gids`, `rpc_set_timeout`. Do not run two event pumps on one context. |
| [`nfsc/libnfs-raw-nfs4.h`](https://github.com/sahlberg/libnfs/blob/libnfs-7.0.2/nfs4/libnfs-raw-nfs4.h) | COMPOUND args/results/unions, `nfs_fh4`, `stateid4`, byte-counted component names, `verifier4`, `stable_how4`; ops PUTROOTFH, PUTFH, GETFH, GETATTR, LOOKUP, LOOKUPP, SAVEFH/RESTOREFH, OPEN/OPEN_CONFIRM/CLOSE, CREATE, READDIR, READ, WRITE, COMMIT, RENAME, REMOVE, SETATTR. Raw-owned-state branch additionally SETCLIENTID, SETCLIENTID_CONFIRM, RENEW, LOCK/LOCKU as needed, DELEGRETURN for unexpected delegations, reclaim via OPEN(CLAIM_PREVIOUS). |

Bindgen allowlists must include transitively required result unions, not handwritten ABI guesses. libnfs API v2 changed read/write signatures and raw `_async` names to `_task`; pin the shared object too. Copy reply data before callback lifetime ends; keep READ/WRITE buffers live until completion/cancellation is resolved. Public `nfs_get_fh` is not a documented export/import of managed NFSv4 state IDs. The inspected public headers have pathname OPEN/opendir, no advertised general `openat(dirfh, name)` constructor; this is the principal risk, not a presumed negative spike result.

## Sequence and observations

| Step | Required experiment / recorded evidence |
| --- | --- |
| 1. Connect | Negotiate wire `minorversion=0` and export anchor; capture actual protocol, config and errors. `nfs_get_version()==4` alone does not prove minor version. Confirm provider credentials are absent from tracee inheritance. |
| 2. Pin anchors | PUTROOTFH→LOOKUP each export/run/root or control component→GETATTR(type, fsid, fileid, change)→GETFH. Reject crossing into another filesystem and physical symlinks. Exercise the managed equivalent without concatenating an unchecked absolute path. |
| 3. Anchored OPEN | **v4.0 OPEN means PUTFH(parent directory)→OPEN(CLAIM_NULL, component)→GETFH/GETATTR**, OPEN_CONFIRM when requested. It is not OPEN(CLAIM_FH) on the target: that claim belongs to later minor versions even if the shared header defines it. Keep an open handle while another client renames/replaces its pathname; old handle must stay on the original object. [OPEN reference](https://www.rfc-editor.org/rfc/rfc7530.html#section-16.16) |
| 4. LOOKUPP / containment | Raw LOOKUPP only as a diagnostic inside the known tree. The provider never traverses above its root/control anchor and does not implement logical `..` by unchecked server LOOKUPP. Race intermediate replacement with a symlink while opening/renaming/removing; verify no out-of-anchor effects. A GETATTR followed by an unrelated path-based OPEN is insufficient. |
| 5. Exclusive creation | OPEN(OPEN4_CREATE, EXCLUSIVE4, persisted 8-byte verifier) with retry-identical name/verifier; lose reply and replay, then try a different verifier. Check flags/rflags/stateid/seqid and later SETATTR for attributes unavailable in EXCLUSIVE4. Verify managed O_EXCL wire behavior, not merely a single AlreadyExists test. |
| 6. Bounded listing | READDIR from cookie 0; retain returned cookie verifier, resume page by page with byte/count bounds and change validation. Mutate directory between pages; explicitly invalidate stale cookies. Measure memory against a large directory; `nfs_opendir` followed by incremental `nfs_readdir` is not proof of bounded server/client buffering. |
| 7. Data/barrier | READ and WRITE by pinned object, including short results. Force a raw WRITE requesting UNSTABLE4; record actual returned stability and verifier. Only a server response below FILE_SYNC needs corresponding commit handling. COMMIT returns verifier; compare before retiring replay data. Specialized raw READ/WRITE task APIs must respect their documented last-op placement. |
| 8. Restart/verifier | Simulate a verifier change in a controlled fake/fault fixture; separately hard-restart disposable Ganesha between unstable WRITE and COMMIT and record whether the verifier actually changes. Matching unchanged values are not evidence of changed-verifier handling. Replay retained exact bytes to the same object after state/authority recovery; observe stable completion. Server-process kill does not qualify storage power loss. |
| 9. Lifecycle | Idle past the lease-renewal interval; transient disconnect; graceful/hard restart and grace/reclaim; SIGSTOP/SIGCONT and callback timeout/cancellation. Prove managed ownership/recovery covers every handle, with errors retained and no use-after-free or unbounded waiting. Do not mistake library reconnection for application lease reacquisition. |
| 10. External coherence | Second userspace client edits/truncates a still-open file and creates/removes/replaces names. Compare fresh bytes/stat/pages and negative lookups without close/reopen dependence for in-place edits. Exercise unlinked/replaced open-file retention; v4.0 may need more than a stale pathname re-open. |

For a missing public API, record the absence and minimal managed extension needed; do not quietly fabricate a function or add production state machinery during the spike. A raw-only diagnostic may demonstrate protocol feasibility using disposable test state; that does not authorize shipping a raw-owned-state client. Stop the managed experiment early when a decisive API gap is established, while retaining a complete gap inventory.

## Verdict and deliverables

- **GO:** all required anchored operations, bounded paging, byte names, existing-handle identity, exclusive-create replay, lifecycle and persistence evidence are available through supported APIs while libnfs remains sole owner of protocol state. Raw stateless diagnostics may coexist only with proven event-pump/lifetime discipline. Supply exact evidence per sequence row.
- **NO_GO:** a required semantic needs private internals, application-owned client/open state, unbounded materialization, unsafe path re-resolution, hidden unrepairable write loss, or unavailable verifier/error evidence. Attach a smallest-work raw plan and updated estimate; pause for human approval **before** raw production implementation. A small proposed upstream managed API extension also requires a concrete separately reviewed plan, not automatic Go.
- **INCONCLUSIVE/BLOCKED:** fixture/network/tooling failure or missing evidence. Never route this to Go or implicitly treat it as approval for raw work.

Future artifacts in the spike worker's isolated worktree: a small standalone Rust program under `experiments/nfs-userspace-spike/` (explicit manifest, outside workspace membership unless deliberately reviewed), allowlisted header wrapper/build metadata, fixture manifest and source-pinned `REPORT.md`. External artifact directory: `spike-result.md`, API capability table, redacted wire/operation trace, memory/deadline measurements, restart/verifier evidence, reproducible commands and exact SHAs. Every report starts with verdict and tested commit; completion is reported only after the entire artifact is written. No credentials, private server paths or unbounded log dumps.

Budget: managed spike 3–5 engineer-days, stopping earlier on decisive gaps. Fresh generated FFI/safe wrapper foundation remains approximately 4–7 days total with overlap; do not double-count spike scaffolding. **Incremental raw-owned-state estimate: 20–35 engineer-days** beyond the binding baseline: state/owner sequencing and anchored OPEN/CLOSE 5–8; renewal/reconnect/grace/reclaim 5–9; stable-write replay/verifier handling 4–7; bounded paging, containment/coherence and fault review 6–11. Single-platform v4.0, experienced engineer, no production claim; excludes M2 syscall/mmap, overlay recovery, M3 fencing/power-loss and Linux/DSM qualification. Wider protocol/API changes must be re-estimated at the No-Go gate.

All future workers use their own worktrees, current repository AGENTS/Memoria instructions, no mounted suites and no access to the existing scratch mount or service. The graph shape is a separate authoring input at `/tmp/nfs-scope/m1-graph-shape.md`; it does not activate this plan.
